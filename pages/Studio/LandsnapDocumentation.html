LandSnap documentation

A practical guide to placing actors on terrain. Start with a selection, snap it to a valid surface, then review and refine the result.

LandSnap 2.0Unreal Engine 5.8Win64Editor-only
Make your first snap →Look up a setting →Solve a problem →
01

Quick start

#

LandSnap snaps selected actors, particle systems, spline components, and spline mesh components onto supported surfaces. All placement work happens in Unreal Editor.

  1. Open the panel. After installing LandSnap, choose Window → LandSnap Panel and dock it beside your viewport.
  2. Select your objects. Start with a rigid mesh actor above a loaded Landscape. Mixed actor and spline selections are also supported.
  3. Choose a surface mode. In Placement Studio → Snap Targets, use Only Terrain Surfaces for Landscape or UE 5.8 Mesh Terrain.
  4. Snap the selection. Click Snap Selected or press Ctrl + ↓.
  5. Inspect the result. Check the viewport and the Needs Review list. Use Undo to restore placement, or review and repair an unresolved result.

Start with the defaults. Tune offsets, trace reach, and size tiers when a particular asset or surface needs it. A rigid object may still need manual adjustment on uneven ground.

04

AutoSnap

#

AutoSnap is one global editor mode. Turn it on to settle eligible placements, duplicates, pastes, and completed edits. It waits for editing to stop before running a snap and verification pass.

  1. Click AutoSnap in the toolbar or press Ctrl + Shift + ↓.
  2. Leave AutoSnap Target Mode at Terrain / Mesh Terrain for terrain placement.
  3. Place or edit one eligible object. After the edit settles, inspect its placement and any review result.
  4. Toggle AutoSnap off when you want to place freely.

Use Snap Selected for multiple actors. AutoSnap ignores edits while more than one actor is selected. Cameras, lights, empty helpers, target terrain, and editor system actors are excluded.

Stock spline-point and spline-mesh endpoint/tangent edits also enter the deferred AutoSnap workflow. Programmatic spline changes that bypass normal editor notifications require an explicit snap.

05

Surface modes

#

Choose your valid targets under Placement Studio → Snap Targets → Surface Types. Terrain-only and tagged-only are mutually exclusive; exactly one surface mode is active.

Choosing a target policy
ModeValid targetsTypical use
Only Terrain SurfacesUnreal Landscape and recognized UE 5.8 Mesh Terrain actors/componentsProps, buildings, and spline placement on terrain
Only Tagged SurfacesActors/components matching your configured surface tagsDesigner-owned roads, platforms, or mesh surfaces

Set up a tagged surface

  1. Add an Actor or Component tag to the intended target, for example SnapSurface.
  2. Add that same tag to LandSnap's allowed surface tags in Snap Targets → Tag Filters.
  3. Enable the corresponding Actor-tag or Component-tag check.
  4. Choose Only Tagged Surfaces and run Snap Selected.

Ignore tags exclude unwanted surfaces. An empty allowed-tag list in tagged-only mode produces no valid target. The mode enables its required Visibility trace fallback automatically; disabling that fallback switches the surface mode back to terrain-only.

Tagged placement is surface-based. The selected object's footprint should reasonably cover the target. Tags do not turn snapping into unrestricted object stacking.

Actors, particles & splines

#
Selection and placement behavior
SelectionWhat LandSnap movesUseful settings
Rigid actor / ordinary componentThe actor; selecting an ordinary component targets its owner.Bounds-bottom or pivot placement, normal alignment, preserved yaw, Z Offset
Niagara / Cascade actorThe actor pivot by default, with rotation preserved.Snap Particle Actors By Pivot; optional particle normal alignment

Rigid actors

Bounds-bottom placement helps objects with off-center pivots rest on the ground. Use pivot placement when the asset's origin is the intended contact point. Surface-normal alignment tilts the object to the target; preserved yaw keeps its heading.

Particle systems

Simulated visual bounds can change between frames, so particle placement uses a stable actor pivot by default and bypasses mesh footprint, convex, concave, and bounce correction. An offset child emitter still follows the actor pivot. Enable Snap Targets → Particle Systems → Align Particle Systems to Surface Normal only for emitters that should rotate with the terrain.

Splines

Select the spline owner or the components directly, then run the same Snap Selected action. Mixed selections can include actors, spline points, and spline meshes. Use the point cap for long splines when alignment updates are expensive.

07

Review & repair

#

Placement is verified against the exact captured target. Questionable results remain in Needs Review, with bounds and status information to help you inspect them.

Reading a result
ResultMeaning / next step
LandedPassed the applicable contact policy. Inspect the visual result for your scene.
3/4 CornersThe retained pose has exactly three measured support corners. Inspect the remaining corner.
FloatingSampled gaps exceed the applicable tolerance. Check collision, offsets, and repair options.
PenetratingSampled burial exceeds the applicable policy. Review terrain shape and the asset footprint.
Wrong surfaceVerification found a different target. Check filters, overlapping surfaces, and collision.
Insufficient target hitsCoverage is incomplete. Load the target region or move the footprint away from its boundary.
Excessive angleAlignment exceeds the applicable angle limit. Inspect the slope and alignment settings.
No initial targetThe initial snap could not find a valid surface. Check target mode, tags, trace reach, and collision.
  1. Use Review Issues, Previous, and Next to inspect entries without changing their placement.
  2. Run Heuristic Repair Selected for the active entry, or Heuristic Repair All Errored for retryable entries.
  3. Watch the bounded candidate search. Use Stop Repair to stop an active job.
  4. Make any deliberate manual correction. Use Mark Resolved when you accept the result; it clears the warning rather than moving the actor or proving new contact.

Repair uses enabled yaw, pitch, roll, and optional uniform-scale candidates. An unsuccessful search restores its post-snap baseline. Ordinary Snap Selected keeps its baseline by default; Enable Heuristic search post Snap opts a single manual actor into the visible search. Multi-actor snapping retains the queued baseline workflow.

Large selections and Undo

Eligible rigid batches prepare across editor frames and publish bounded groups under one Undo step. Keep Published Batches When Cancelled is on by default: an explicit Cancel keeps completed, target-verified groups and leaves pending actors unchanged. Disable it for all-or-nothing cancellation. Settings, world, or Undo/Redo interruptions restore the original invocation.

09

Size tiers

#

Size tiers tune trace reach, convex thresholds, and bounce correction for different asset scales. Choose an automatic classifier or a manual tier. Tier selection itself does not choose a different placement solver.

Automatic sizing

The default Mixed range is 100–25,000 cm, using logarithmic buckets. Select a size source: scaled Mesh Asset Bounds, Render Bounds, or Actor Bounds. Values outside the range clamp to the smallest or largest tier.

Auto range profiles
Range profileRange (cm)Use
Props25–3,000Small to medium props
Mixed100–25,000General scenes; default range
Large Structures500–200,000Large architectural assets
CustomYour Min / MaxA project-specific range

Log uses logarithmic spacing; Linear uses evenly spaced size bins; Quantile uses selection-derived thresholds. Use Auto-Range From Selection (p5/p95) to derive bounds, or Rebuild Quantiles From Selection to rebuild Quantile thresholds.

The separate asset profile can be Auto, Props, Architecture, Foliage / Organic, Vehicles, or Custom. Auto resolves it per actor from tags, class, and shape. The Custom asset profile disables tier overrides and uses manual advanced values.

10

Large objects & terrain

#

Rigid placement uses representative bottom-footprint samples rather than every underside vertex. Ordinary coverage uses nine points: four corners, four edge midpoints, and the center.

Eligible Landscape footprints at least 500 UU (5 m) on both local axes can use nine exact-target terrain heights to infer pitch and roll, followed by corner seating and bounded support-edge fitting. This physical-large policy is separate from the size-tier classifier.

Convex Saddle describes a crest, Concave Saddle a bowl, and Diagonal Saddle opposing curvature. These labels describe measured terrain shape. They do not alone prove contact or successful recovery; unresolved results stay visible for review.

Precision has a scope. The ordinary 0.5 cm gap/penetration audit threshold is measured along the captured target normal. It does not promise 0.5 cm world-Z accuracy or continuous contact beneath an entire building. Large fitting has its own bounded contact/burial policy.

World Partition and terrain boundaries

Load the relevant cells so target collision can be sampled. Leave room around a footprint for rotation: an object near a Landscape edge may tilt beyond available coverage and remain unresolved. Landscape streaming proxies belonging to the same Landscape GUID are recognized as the same logical target.

Experimental Mesh Terrain deformation

Ordinary Mesh Terrain snapping works independently of deformation. For optional terrain shaping, enable Setup → Experimental Settings → Enable Mesh Terrain (Experimental). This reveals Mesh Terrain Settings(Experimental) with Deform Under Selected and the default-off Deform After Snap workflow.

The owned modifier supports a grayscale deformation map, blend behavior, depth, footprint padding, falloff, and priority controls. Repeated actions update or replace the owned component instead of stacking duplicates.

Experimental workflow. Deformation applies to UE 5.8 Mesh Terrain, not standard Landscape heightmaps or tagged static meshes. Its world-space XY footprint may need a custom map for irregular foundations, stairs, or basements.

#

Domino exposes ten size references from XXXTiny through XXXLarge, with a default 8.73% cube-width gap. The selected tier sizes the fixture; snapping still uses your production classifier and tuning.

Complete fixtures can be reselected after moving or snapping them. Creation fails closed on partial, mismatched, mixed, or colliding ownership evidence. Clean targets exact-owned loaded fixtures independently of the current dropdown; it does not broadly delete actors by label or folder. Load relevant regions and resolve unloaded fixture conflicts before proceeding.

12

MCP integration

#

The included LandSnapMCP editor module lets a compatible client inspect settings, snap a bounded selection, verify exact targets, and run review repair. Epic's UE 5.8 MCP and Toolset Registry features are experimental; core manual placement remains independent.

  1. Open Setup → MCP and choose Enable Agent Integration, or Configure Agent Integration if onboarding was dismissed.
  2. Confirm the editor's setup prompt. Restart when requested if Epic's Model Context Protocol plugin was newly enabled or its URL path changed.
  3. Connect your client to the local endpoint, normally http://127.0.0.1:8000/mcp.
  4. Discover LandSnapMCP.LandSnapToolsetDefinition and inspect the available tools. With Unreal tool search enabled, use list_toolsets, describe_toolset, and call_tool.
Transport and mutation are separate opt-ins
CapabilityRequirement
Read-only statusConfigured local transport; try GetStatus.
Agent-driven changesSet Windows User environment variable LANDSNAP_AGENT_ENABLED to 1 before launch, restart the launcher/editor, and confirm Agent mutations: Enabled.
Provider credentialsLandSnap requires no provider API key. Any credentials belong to the external client and should stay in operating-system environment variables.

Keep the endpoint on loopback. Transport activation does not grant mutation permission. The adapter works with selected actors, exact paths, and Outliner folders; it does not create, position, or select actors itself.

13

Troubleshooting

#
Common symptoms and first checks
SymptomFirst checks
No movement / no targetConfirm selection, surface mode, allowed tags, loaded collision, and trace reach. Terrain target actors and unsupported editor helpers are not placement objects.
Object floats or sinksInspect pivot/bounds-bottom choice, Z Offset, mesh collision, and terrain shape. Use the review result to guide repair.
Missing simple collision warningInspect the Static Mesh asset's collision. Missing or inaccurate collision can reduce trace reliability even when the visible geometry looks correct.
Tagged surface is ignoredCheck allowed tags and tag-check scope, ignore tags, target collision, and Only Tagged Surfaces. The allowed list must not be empty.
AutoSnap ignores an editCheck the global toggle and single-actor selection. Z-only edits are preserved by default; rotation-only edits may be preserved when fine-tuning is enabled.
Emitter rotates unexpectedlyDisable particle normal alignment to preserve actor orientation.
Toolbar button is absentUse Window → LandSnap Panel and check Setup → Configure Hotbar.
Large batch is slowWork in bounded groups, review frame-budget controls, and turn off unnecessary debug drawing/logging.
Footprint loses target coverageLoad the relevant World Partition cells and allow an inset from the terrain boundary for tilt.
Agent mutation is blockedConfirm the OS environment flag was set before the editor and launcher started. Read-only transport availability does not enable mutation.

Limits to expect

Very thin meshes, extreme slopes, highly concave targets, and broad rigid footprints may need tuning or manual placement. A bounded repair search may finish without a conforming result. Inspect the final pose and keep unresolved results visible until you make an intentional decision.

For help, contact Nightshift with your engine version, target type, relevant settings, and a screenshot of the selection and review result.
